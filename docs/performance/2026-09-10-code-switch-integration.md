# 联动性能验证

2026-09-10，Apple M4、macOS 27、Swift 6.4（SDK 26.5 / Swift 5 模式）、Go arm64。
数据均为临时目录中的合成供应商，Go 复用隔离测试数据库；没有调用真实供应商接口。
没有预设性能预算，以下记录测量值，不据此宣称整应用性能达标。

## Codenotch 接收端

以下静态与启停数据记录初次实现；评审修正后的动态负载与自定义 CLI 对照见后文。

使用 `Scripts/benchmark-code-switch.swift`，每种规模/模式启动独立进程、执行 1000 次读取。
合成供应商各含一个每日配额，无真实会话及网络；计时包含文件属性查询、读取和状态更新。
CPU 为 `getrusage` 的用户＋内核时间，RSS 为整个测试进程的峰值字节数换算成 MiB。
驱动以 `-O` 编译，链接用于回归的未优化应用模块；不能代替 Release 应用实测。

`decode` 是每次重新解码同一文件的参考负载，使用当前状态投影缓存，**不是旧版本整应用基线**；
`cached` 使用新读取器的同一托盘文件，`full` 使用小主文件＋完整供应商文件。
文件在 1000 次读取期间不变，因此不含实际运行时每秒更新的小主文件解码成本。

| 供应商 | 重复解码 CPU ms | 托盘缓存 CPU ms | 全量修订缓存 CPU ms | 全量缓存峰值 RSS MiB |
| --- | ---: | ---: | ---: | ---: |
| 10 | 143.05 | 86.76 | 93.77 | 13.38 |
| 100 | 498.83 | 69.42 | 81.81 | 13.94 |
| 500 | 2177.17 | 68.00 | 83.16 | 15.48 |

参考负载每轮解码 1000 次；托盘缓存仅解码主文件 1 次；全量缓存仅解码主文件和完整数据各 1 次。
500 条全量缓存的 1000 次读取墙钟时间为 138.66 ms。

额外执行每种规模 1000 次“订阅全量→读取→撤销清空”，完整文件每轮重新解码：

| 供应商 | 1000 次启停 CPU ms | 峰值 RSS MiB |
| --- | ---: | ---: |
| 10 | 838.86 | 13.95 |
| 100 | 1324.10 | 14.59 |
| 500 | 3790.79 | 16.48 |

RSS 可能因分配器保留页面而不立即下降，不能仅凭 RSS 证明没有泄漏。
回归另行检查关闭后发布数组/绑定为空、订阅移除、迟到任务不能重建订阅；actor 清空解码缓存与投影状态。
本次未采集 Swift 对象级分配计数，也没有桌面 UI 帧率数据。

## Code Switch R 发送端

使用 `services/codenotch_integration_test.go` 的 `BenchmarkCodenotchCollection` 与 `BenchmarkCodenotchChurn`。
每组固定 1000 次、重复 3 次，下表为耗时中位数与对应规模的近似分配量。
托管状态由测试闭包返回；不含读取真实平台配置及网络/数据库刷新耗时。

| 供应商 | 未变采集 ms/次 | 分配 bytes/次 | allocs/次 | 快照 bytes | 启停 ms/轮 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 | 0.019 | 16,599 | 76 | 2,032 | 0.396 |
| 100 | 0.055 | 121,608 | 449 | 16,073 | 0.634 |
| 500 | 0.220 | 624,641 | 2063 | 79,273 | 1.534 |

快照大小为基准序列化载荷（空发布者 session），实际文件会多出 session 等少量字节。
稳态完整列表始终只写一次；调度频率约 1 秒一次，不把以上分配量乘以高频 UI 刷新次数。
全部 18 组基准的测试进程峰值 RSS 为 48,431,104 bytes（46.19 MiB），用户 CPU 9.68 秒、内核 CPU 4.19 秒；
包含 Go runtime、服务依赖和测试数据库，不是新增功能独占内存。
全量模式为新增功能，没有旧版同功能基线。

无订阅测试确认 0 次额外托管状态查询、0 条额外详情缓存；HTTP 测试确认同时仅 4 个查询，
重复调度不重复启动、取消后全部退出，托盘仍需要的任务不会被撤销。
每轮启停检查输入与详情缓存清空；请求代次回归检查迟到结果被丢弃。

## 评审修正后的动态与配置检查

发送端增加 `BenchmarkCodenotchCustomHosting`，使用相同的 10/100 个自定义 CLI 配置和目标 JSON 文件，
对比“先取列表再逐工具调用公共 ProxyStatus”与“先取列表再复用本轮配置”。每组 100 次、重复 3 次，取耗时中位数。
目标文件的代理地址和兼容鉴权检查均真实执行，所有内容为隔离测试数据。

| 自定义工具数 | 原读取方式 ms/轮 | 复用配置 ms/轮 | 原分配 bytes/轮 | 复用后 bytes/轮 |
| --- | ---: | ---: | ---: | ---: |
| 10 | 0.578 | 0.182 | 159,617 | 37,056 |
| 100 | 28.610 | 1.634 | 11,815,393 | 362,531 |

100 个工具的耗时减少约 94%，分配量减少约 97%；这里的分配量不是常驻内存。
原方式每轮解析工具列表 101 次，新方式 1 次；两组仍各读取 100 个目标配置文件。

发送端 `BenchmarkCodenotchDynamicCollection` 每组 100 次、重复 3 次：
10/100/500 个 Codex 供应商外加 10 个自定义工具，轮换请求供应商和会话绑定，每 10 轮写一次工具配置。
包含采集、配置读写和完整文件发布；内建平台托管状态仍由闭包提供，不含远程配额或日统计查询。
各轮全量文件写入次数均为 1，修订序号检查通过；HTTP 回归另行确认有效期内重入只查询 1 次，到期和查询配置变更才分别新增查询。

| Codex 供应商数（另加 10 个工具） | 动态采集 ms/轮 | 分配 bytes/轮 | allocs/轮 |
| --- | ---: | ---: | ---: |
| 10 | 0.447 | 83,280 | 746 |
| 100 | 0.463 | 196,026 | 1206 |
| 500 | 0.921 | 719,169 | 3217 |

接收端增加 `heartbeat` 和 `dynamic` 两种负载，各执行 1000 轮。
前者每轮重写主文件但保持完整修订不变；后者额外每 10 轮改变供应商信息、活跃请求和会话绑定，推进完整修订。
计时包含合成发送端的编码及原子写入，因此不能作为接收端独占 CPU 或与上方静态读取直接比较。

| 供应商 | 心跳负载 CPU ms | 动态负载 CPU ms | 动态进程峰值 RSS MiB |
| --- | ---: | ---: | ---: |
| 10 | 516.70 | 699.33 | 14.19 |
| 100 | 589.05 | 733.02 | 15.14 |
| 500 | 618.44 | 1195.33 | 17.95 |

两种负载均解码主文件 1000 次；心跳负载仅解码完整文件 1 次，动态负载恰好 100 次。
500 条动态负载墙钟时间为 1356.63 ms。该负载验证动态修订的处理成本与未变修订复用，不代表真实应用会话分布或 UI 性能。

## 复现与功能检查

发送端：

```sh
go test -mod=readonly -race ./services -run '^(TestHookSession|TestTray|TestCodenotch)' -count=1
go test -mod=readonly ./services -run '^$' -bench '^BenchmarkCodenotch(Collection|Churn)$' -benchmem -benchtime=1000x -count=3
go test -mod=readonly ./services -run '^$' -bench '^BenchmarkCodenotch(CustomHosting|DynamicCollection)$' -benchmem -benchtime=100x -count=3
```

接收端：将 `Scripts/benchmark-code-switch.swift` 链接到启用 testing 的 Codenotch 模块后，
分别运行 `BridgeBenchmark decode 500` / `cached 500` / `full 500` / `churn 500`，规模可替换为 10、100。
驱动输出 JSON，包含 CPU、墙钟时间、RSS 及解码次数。
动态模式为 `BridgeBenchmark heartbeat 500` / `dynamic 500`，规模同样可替换为 10、100。

Swift 69 项回归、应用源码编译、中英文文案校验、Go 定向 race 检查和主包编译通过。
环境只有 Command Line Tools，且无可用桌面屏幕；未运行完整 Xcode/Wails 打包和实际窗口交互验收。
