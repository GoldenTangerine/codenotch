# Code Switch R 联动

Codenotch 的独立设置页保存 `codeSwitchEnabled`（沿用原值，默认开启）、
`codeSwitchDisplayMode`（`tray` 默认 / `enabled`），及隐藏供应商 ID 集合和供恢复使用的名称。
隐藏按平台和供应商 ID 隔离，对两种模式及关联会话生效，不影响本地账户、CLI hooks、上游开关和上游配额查询。
供应商暂时离开推送范围时，保留用户主动隐藏的选择；不积累全部历史快照。

设置页采用摘要表格：拖动/显示、供应商/平台、今日请求与费用、主要额度、详情展开按钮。
成功率、Tokens、首字延迟、速度、全部额度与重置时间在行内详情展示，额度根据宽度自动并列。
表头随纵向滚动固定，供应商行延迟布局，不新增网络查询或轮询。
今日 Tokens 与发送端首页保持一致，为输入、输出与缓存读取之和；成功率无有效请求时显示横线，
首字延迟小于 1 秒使用毫秒。未取得统计时显示横线，真实零读数保留 0；余额、无限额、未开始及异常额度分别展示。
搜索匹配名称、平台及供应商编号；同名条目显示编号。仅隐藏过的离线条目保留恢复入口，标注当前未同步，不携带伪造统计。
会话关联可以补充供应商身份和隐藏入口，但只有当前 `snapshots` 中的供应商可展示统计与额度；
仅在 `bindings` 中的条目标注会话供应商，统计为横线、额度为当前未同步，重新同步后自动恢复。
按默认内容区 484/680 × 468 及放大后的窗口验证表格。窗口最小内容尺寸 680 × 520，
通过 AppKit 保存与恢复窗口位置和大小，缩放后重新定位窗口按钮。
图标与名称同行，摘要展示异常或使用比例最高的一项额度；额度颜色复用 `UsageBand`，不被强调色覆盖告警等级。
额度复用快照已解析的 `windows`，按原额度顺序对应有效窗口，不能用 key 合并重复额度或错配异常项。
可见的重置时间按分钟更新显示，不增加 IPC 或供应商查询频率。

`codeSwitchProviderOrder` 仅存储本地联动供应商 ID 顺序，不改写发送端配置或本地账户顺序。
拖放完成时保存一次；搜索非空时禁用拖动，不接受其他列表或外部应用的拖放数据。
拖动手柄命中区为 24 × 32；按目标行上下半区显示插入线并插入其前后，原位置落下不写入偏好。
系统拖动会话取消或拒绝时清空状态；成功结束先清除提示，保留令牌直至数据交付，避免异步落点回调丢失。
迟到会话回调按令牌隔离，不能清理后续拖动状态；不添加轮询或全局事件监听。
拖动时只置换当前列表中的位置，暂时离线且不在列表中的已保存条目保留原位置；隐藏条目仍参与设置列表排序。
无保存顺序时设置与刘海均按名称、平台、ID 排列；刘海在会话归属、临时入口与隐藏过滤完成后应用同一顺序，仅置换联动供应商的位置。
本地账户与未关联的 CLI 入口位置不变；新供应商排在已排序条目后，以名称、平台和 ID 确定稳定顺序。

`enabled` 的资格为 **平台开启代理托管 AND provider.Enabled**，与是否正在处理请求无关。
排序先沿用托盘/首页平台顺序，再补 Claude、Codex、Gemini、Grok Build、Claude Desktop，
最后按 ID 排序补齐自定义 CLI；排除 OpenCode、OpenClaw、Hermes、Pi 等非托管平台。
平台内保留配置顺序。Claude/Codex 会话归属复用已有 bindings，运行中、等待及短暂完成提示可临时保留超出范围的供应商；显式隐藏优先。

Codex 原生监测保留会话目录中的 thread ID，并生成与 hooks 同口径的供应商关联键。
原生身份与 hook 通知身份分开存储，避免把原生日志活动误当成 hook 生命周期事件。
同一会话的原生记录与 hooks 精确归并；未关联的 Codex 仅在等待回答/审批及短暂完成提示时创建 CLI 入口，
回答后不因遗留的 busy 状态持续展示空白圆环。存在未隐藏的联动供应商时，过滤没有读数也没有错误的本地 Codex 占位账户；全部隐藏后保留独立本地入口。

## 文件和协商

所有文件固定在 `~/Library/Caches/code-switch`，不接受快照指定的外部路径。
写入通过同目录私有临时文件和原子重命名完成；目录 `0700`、文件 `0600`。

| 文件 | 内容 | 生命周期 |
| --- | --- | --- |
| `tray-snapshot-v1.json` | 现有 version/session/sequence/heartbeatAt/platforms；可选 codenotch 元数据 | 维持原托盘口径，约 1 秒心跳 |
| `codenotch-subscription-v1.json` | version=1、随机 session、mode=enabled、heartbeatAt（毫秒） | Codenotch 每 5 秒续约；15 秒过期，未来偏差最多 1 秒 |
| `codenotch-providers-v1.json` | version=1、发布者 session、revision、platforms | 全量数据变化或文件被删除、外部改写后重建 |

主文件 `codenotch` 字段：`version=1`、`mode`、`consumerSession`、`revision`、`error`。
读取全量前校验消费者身份；数据文件必须匹配主文件的发布者身份和 revision。
订阅 `heartbeatAt` 写入 Unix 整数毫秒；发送端兼容 Codenotch v1.6.12 曾写入的小数毫秒，
按毫秒数值验证 15 秒有效期和最多 1 秒的未来偏差，不能用整数 JSON 解码拒绝有效订阅。
旧发送端无扩展或版本不兼容时显示升级提示，暂用托盘；收到兼容扩展后自动切换。
可选扩展单独容错解码：缺失、null 或格式异常均按无扩展处理；基础协议必填字段仍严格校验。
尚未确认订阅时显示等待状态；数据损坏、修订不一致或发布失败会提示并自动重试，暂用托盘。
平台错误独立显示为部分不可用，不把失败平台的旧供应商继续作为当前数据。

订阅上限 4096 字节，两类快照分别上限 2,000,000 字节。超限明确报错，不静默截断。
主心跳超过 3 秒或主文件删除后隐藏联动数据；临时损坏最多保留此前数据到原心跳过期。
正常退出/关闭/切回托盘撤销自己的订阅，不删除另一实例的订阅；发布者也只删除自己的数据。

## 资源约束

- 发送端约每秒检查订阅与资格，只在有效全量订阅时采集额外平台。
- 托盘和全量供应商按身份合并查询，最多 4 个并发任务，60 秒刷新资格，按最久未调度顺序避免饥饿。
- 移出全部需求的供应商立即取消任务；每次请求带序号，旧请求结果不能覆盖重试。仍由托盘需求持有的任务继续运行。
- 近期托盘条目的未过期配额结果可短暂保留，最多 128 条非当前需求结果，最长至最后托盘展示或结果读取后 60 秒；不保留对应查询输入。仅全量模式需要的条目撤销后立即回收。
- 每个平台的日统计缓存 60 秒并建立供应商索引；移出需求后释放输入和统计缓存。
- 自定义 CLI 每轮全量采集复用一份工具配置快照，逐工具检查目标文件；下轮重新读取配置以响应编辑。
- 发送端通过文件身份、大小、修改时间检查全量文件是否被改写，异常时重新发布并递增修订；未变文件不重复读入或解码。
- 接收端后台 actor 串行读取，定时器与文件通知合并；未变的 inode/大小/修改时间跳过主文件解码，未变的修订跳过全量解码。
- 主线程只发布变化的展示状态。设置列表使用延迟布局，隐藏过滤发生在会话关联之后，避免重新插入隐藏供应商。
- 退出前等待撤销完成；崩溃则依赖租约过期回收。旧发布者身份仅保留最近 16 个。
